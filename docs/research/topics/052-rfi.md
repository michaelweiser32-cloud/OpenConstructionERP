# 052. RFI Workflow (ball-in-court, due dates, distribution, linking to drawings)

## What it does
A Request for Information (RFI) is how a contractor or sub asks the designer or owner to clarify the contract documents. A working RFI workflow does four things. It tracks **who holds the ball** at each step: draft, then the assignee or reviewers, then back to the creator. It sets and enforces **response due dates**, counting working days and sending overdue reminders. It keeps a **distribution list** of people who are copied and can follow the thread or reply by email. It **links the question to specific drawing sheets or locations**, and ideally to the answer's drawing revision. The industry reference is the AIA G716 form. That form lists the documents the requester reviewed, includes the sender's recommendation and the receiver's response, and states that an RFI response does not by itself change cost or time.

## Already in the codebase (with file paths)
The module is fairly mature, so this report covers the gap, not a new feature.
- `backend/app/modules/rfi/models.py` has `ball_in_court`, `assigned_to`, `response_due_date`, `date_required`, `cost_impact`/`schedule_impact`, `linked_drawing_ids` (a JSON array of document UUIDs) and `change_order_id`.
- `backend/app/modules/rfi/service.py` enforces status transitions (draft, open, answered, closed or void). It sets the due date automatically to 14 business days when an RFI opens, clears the ball-in-court on close, and publishes the `rfi.assigned`, responded and closed events.
- `backend/app/modules/rfi/router.py` provides CRUD, stats (open, overdue, average response time), Excel log export, bulk delete and status changes, `respond`, `close`, and `create-variation` (RFI to change order).
- `backend/app/core/event_handlers.py` (around line 1254): only `rfi.assigned` sends an in-app notification.
- `frontend/src/features/rfi/RFIPage.tsx` (about 1,250 lines) is the UI. `is_overdue` and `days_open` are computed when the API builds each response.

**Gaps:**
- There is no distribution, CC or watcher list, and no private or confidential flag.
- Ball-in-court holds a single user. It cannot hold several reviewers, and the "remaining reviewers" logic that the ACC v3 RFI API offers is missing.
- No scheduled overdue or upcoming-due reminders exist. A model for one is the existing asyncio KPI loop in `backend/app/main.py`.
- The due-date default and working-day calendar are not configurable per project.
- No notification fires on response or close. Nothing goes out through `integrations/email_service.py`, Slack or Teams, and there is no reply-by-email intake.
- Drawing links are bare UUIDs. There is no sheet and revision snapshot, no pin or markup location (the `markups` and `dwg_takeoff` modules are not linked), and no "superseded drawing" flag.
- There is no AIA-G716-style PDF output.

## Who it helps and how much
- **Small GCs and subs**: high value. Unanswered RFIs are a main cause of delay claims. Clear ball-in-court data and automatic reminders replace spreadsheet chasing.
- **Estimators**: medium value. RFIs raised during bidding clarify scope. The existing RFI-to-variation link turns answers into priced change orders.
- **Owners and designers** who receive RFIs: medium value. Distribution emails let them reply without a login.

## Implementation effort (Small/Medium/Large, module(s) touched, sketch of how it plugs into the module system)
**Medium**. Modules touched: `rfi`, `notifications`, `integrations`, `documents` and `markups`. A sketch:
1. **Distribution list.** Add an `rfi_distribution` table (rfi_id, user_id or contact_id, role in [assignee, reviewer, watcher]) or a JSON column, and an Alembic migration. Fan out `rfi.*` events to everyone on the list through new handlers in `event_handlers.py`.
2. **Multi-reviewer ball-in-court.** Change `ball_in_court` to a list and add `remaining_reviewers`. When the last reviewer responds, the ball returns to the creator, which mirrors Procore's "Return to Creator's Court".
3. **Due-date policy.** Store default days and a calendar or holiday list in project settings (regional packs can supply holidays). Add a daily task that emits `rfi.due_soon` and `rfi.overdue`. Use the in-process asyncio loop for small installs and Celery beat when Redis is available.
4. **Drawing links.** Replace the bare `linked_drawing_ids` with objects shaped like `{document_id, sheet_no, revision, markup_id?, x, y}`. Show an RFI pin on the sheet viewer, and flag the link when a newer revision arrives through `cde` or `documents`.
5. **Validation rules** (required by the project guide, file `validation/rules/rfi.py`): an open RFI without a due date, without an assignee, or with no linked document triggers a warning.
6. **PDF output** in a G716-like layout, using the existing reporting stack.

## Building blocks (free/open-source libs, APIs, MCP servers — each with a link and license/pricing note)
- **Procore RFI data model** (as a design reference, not a dependency). The public support docs cover ball-in-court, distribution, private RFIs and the default due-date setting: https://support.procore.com/products/online/user-guide/project-level/rfi/glossary-project-rfis. The Procore API needs a developer account.
- **Autodesk ACC RFIs API v3**, with ball-in-court arrays, `remainingReviewers` and `permittedActions`: https://aps.autodesk.com/en/docs/acc/v1. It is useful for an import or sync connector. The API is free with APS, but ACC requires a subscription.
- **procore-mcp-server** (community, MIT, unofficial): https://github.com/TylerIlunga/procore-mcp-server.
- **aps-mcp-server-nodejs** (under Autodesk's own GitHub organization; I did not check its license): https://github.com/autodesk-platform-services/aps-mcp-server-nodejs. I found no official Procore MCP server.
- **AIA G716** form, used as a layout and field checklist. It is a paid AIA document, so copy the fields, not the form text: https://help.aiacontracts.com/hc/en-us/articles/1500009325281.
- **Celery beat** (BSD-3) for reminders, already a dependency: https://docs.celeryq.dev/en/stable/userguide/periodic-tasks.html.
- **python-holidays** (MIT) for working-day due dates: https://github.com/vacanza/holidays.

## Priority: 4/5 — Core module exists; distribution, reminders and real drawing links are cheap, high-impact gaps for small contractors.
