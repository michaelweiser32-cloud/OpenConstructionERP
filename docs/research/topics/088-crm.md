# 088. CRM for GCs and Owners (leads, opportunities, bid pipeline, HubSpot/Pipedrive sync)

## What it does
A construction CRM tracks the *pre-contract* phase: incoming leads (invitations to bid, owner enquiries, referrals), qualification with a weighted go/no-go score, opportunities moving through GC-specific stages (Lead → Qualified → Go/No-Go → Pursuit → Bid Submitted → Won/Lost), due dates, estimated value, probability, and win/loss reasons. Once won, the opportunity becomes a Project and its estimate becomes the BOQ baseline. Optional two-way sync with HubSpot or Pipedrive keeps an existing sales CRM aligned instead of replacing it.

## Already in the codebase (with file paths)
- **Contacts / companies**: `backend/app/modules/contacts/models.py` has a strong party model (company, VAT, prequalification, insurance, certifications, payment terms). This is the "accounts" half of a CRM.
- **Projects**: `backend/app/modules/projects/models.py` has `status` and `budget_estimate`, but no lead/opportunity stage, probability, or source.
- **Outbound bidding**: `backend/app/modules/tendering/models.py` (`TenderPackage`, `TenderBid`) and `backend/app/modules/rfq_bidding/models.py` (`RFQ`, `RFQBid`) cover *subcontractor* bids we receive, not the GC's own pursuits sent to owners.
- **Integrations**: `backend/app/modules/integrations/` has outgoing webhooks (`oe_integrations_webhook`) plus Slack/Teams/Telegram/email, which can carry CRM events.
- **Gap**: no `crm` module, no lead/opportunity/pipeline entities, no win-rate reporting, and no HubSpot/Pipedrive connector. A grep for `hubspot|pipedrive|opportunit` across modules returns nothing relevant.

## Who it helps and how much
- **Small GCs and estimating firms** (high value): a bid board with due dates and go/no-go stops missed deadlines and low-margin pursuits. Win/loss data feeds estimate benchmarking. Vendor guides claim systematic CRM use raises commercial win rates from about 20-25% to 30-40%. These figures are self-reported, so treat them as directional only.
- **Owners/developers** (medium value): a pipeline of planned projects and the consultants and contractors linked to each.
- Review sites note that construction platforms in general are strong on project execution but weak on pre-construction pursuit tracking. That gap is a differentiator for an estimating-first ERP.

## Implementation effort
**Medium**, new module `backend/app/modules/crm/` plus a frontend feature `frontend/src/features/crm/`.
- `manifest.py`: `name="oe_crm"`, `depends=["oe_projects", "oe_contacts"]`.
- `models.py`: `Lead`, `Opportunity` (stage, value, probability, due_date, source, go_no_go_score JSONB, loss_reason, contact_id FK, project_id FK nullable), `PipelineStage` (configurable per tenant), `Activity`.
- `service.py`: "convert to project" creates a Project and a draft BOQ, and publishes `crm.opportunity.won` / `crm.opportunity.lost` on the event bus.
- `validators.py`: rules such as `crm.due_date_required`, `crm.value_without_estimate`, `crm.stale_opportunity` (validation is mandatory per project rules).
- Kanban board in the frontend, plus a win-rate and pipeline-value widget in `reporting`.
- **Sync (separate optional plugin, e.g. `oe_crm_hubspot` / `oe_crm_pipedrive`)**: map Contact↔Company/Organization and Opportunity↔Deal, using webhooks inbound and a scheduled delta pull. Add these as tools in `erp_chat/tools.py` so the assistant can say "what bids are due this week". Conflicts are resolved by a human, never by an automatic overwrite.

## Building blocks
- **HubSpot CRM API v3** (deals, pipelines, companies). Free CRM tier includes API access. Private apps: 100 req/10 s and 250k/day on Free/Starter. https://developers.hubspot.com/docs/developer-tooling/platform/usage-guidelines
- **HubSpot remote MCP server** (`mcp.hubspot.com`, OAuth, reported GA in April 2026, works on all tiers including free). Third-party sources report that it does not cover custom objects. I could not fetch the primary docs from this session, so verify there. https://growthmethod.com/hubspot-mcp-server/
- **Pipedrive REST API v1/v2 + webhooks**: API token or OAuth on every paid plan (from about $14 per seat per month), with token-budget rate limits. https://www.pipedrive.com/en/features/crm-api
- **Pipedrive MCP**: I found **no official server**. Community options exist, e.g. https://github.com/WillDent/pipedrive-mcp-server (read-first, gated writes) and https://github.com/ckalima/pipedrive-mcp-server. Audit them before use.
- **Open-source alternatives / reference designs**: SuiteCRM (AGPL-3.0) https://github.com/SuiteCRM/SuiteCRM; EspoCRM (AGPL-3.0); Twenty (mostly AGPL-3.0 with some files under a commercial Enterprise license). These are AGPL-compatible as reference designs or sync targets, but an embedded mini-CRM is lighter than shipping any of them.
- **Python**: `httpx` (already the typical stack) is enough. Official SDKs are optional: `hubspot-api-client` (Apache-2.0) and `pipedrive-python`.

## Priority: 4/5 — the bid pipeline and go/no-go are core to a small GC's revenue and fit the existing contacts/projects modules, while external CRM sync can follow later as an optional plugin.
