# 044. Box connector for drawings and documents

## What it does
A Box connector links a project in OpenConstructionERP to a folder in a company's Box account. Users can:
- browse Box and pick files (PDF drawings, DWG/RVT/IFC models, specs) and import them into `documents` / `cde`, which starts the usual parse, validate and enrich pipeline;
- keep a two-way link, so a new revision uploaded to Box shows up as a new document revision in the ERP;
- push generated outputs back to a chosen Box folder, such as BOQ exports, GAEB files, tender packages and transmittals.

Optionally, `erp_chat` could also search Box content through Box's hosted MCP server.

## Already in the codebase (with file paths)
- `backend/app/core/storage.py`: a `StorageBackend` abstraction with `LocalStorageBackend` and `S3StorageBackend`. This stores blobs. It does not sync with a user's cloud drive.
- `backend/app/modules/documents/router.py`: upload, photos, sheets and PDF split endpoints (`/upload/`, `/sheets/split-pdf/`). This is the natural place to land imports.
- `backend/app/modules/cde/`: ISO 19650-style containers and suitability states (`suitability.py`). Box revisions would map onto these.
- `backend/app/modules/integrations/`: outgoing webhooks (`models.py`: `WebhookEndpoint`, `WebhookDelivery`) and chat connectors (Slack, Teams, Telegram, WhatsApp, Discord, email). These use webhooks only. **There is no OAuth2 token store yet**, and there is **no Box, Dropbox, OneDrive, Google Drive or SharePoint code** anywhere in `backend/app` or `frontend/src`.

Gap: nothing for Box exists. A shared "cloud drive" OAuth plus sync layer would also be needed, and it would serve future Drive, Dropbox and OneDrive connectors too.

## Who it helps and how much
- **Small general contractors and estimators whose architects or owners already share drawing sets through Box.** A connector ends the manual re-upload step and the version drift it causes.
- It helps less in DACH and other markets where SharePoint/OneDrive, Google Drive or Dropbox are more common. For many small firms a generic cloud-drive connector, with Box as one provider, is worth more than a Box-only build.

## Implementation effort (Small/Medium/Large, module(s) touched, sketch of how it plugs into the module system)
**Medium.** Build it as a new module `backend/app/modules/box_connector/` (`manifest.py` with `depends=["oe_documents", "oe_cde", "oe_integrations"]`, `auto_install=False`):
1. **Auth:** OAuth 2.0 (3-legged) per tenant or user. Encrypted refresh-token table in `models.py`, plus a `/connect` and `/callback` router.
2. **Picker:** the frontend embeds the Box UI Elements Content Picker (React) in `frontend/src/modules/box/`. The selected file IDs go to `POST /api/v1/box_connector/import/`.
3. **Import:** `service.py` downloads each file with the official Python SDK, writes it through `StorageBackend.put`, creates a `documents` record carrying `metadata.box_file_id` and `box_version_id`, and publishes `documents.imported` on the event bus. The existing validation pipeline then runs. Validation stays mandatory.
4. **Sync:** register a Box V2 webhook (`FILE.UPLOADED`, `FILE.NEW_VERSION` …) on the linked folder. Verify the `BOX-SIGNATURE-PRIMARY` signatures, and queue a new revision in `cde` for human review. No automatic overwrite.
5. **Export:** add a hook on reporting and tendering exports that offers "Save to Box".
6. **Validation rules:** file-type allowlist, maximum size, duplicate-version detection, missing-metadata warnings.

Build the OAuth and sync core as a reusable `cloud_drive` base, so that Drive, Dropbox and OneDrive later only need adapters.

## Building blocks (free/open-source libs, APIs, MCP servers — each with a link and license/pricing note)
- **Box Python SDK (`box-sdk-gen`, also published as `boxsdk>=10`):** https://github.com/box/box-python-sdk-gen. Apache-2.0.
- **Box UI Elements (Content Picker / Preview / Explorer):** https://github.com/box/box-ui-elements. Open source, but I have not confirmed the exact licence terms. Check the licence before bundling it in AGPL code. A self-built picker using the folder-listing API is the fallback.
- **Box V2 Webhooks:** https://developer.box.com/guides/webhooks/v2. Signed deliveries, triggers on specific files and folders.
- **Box Remote MCP server (official, hosted at `https://mcp.box.com`, OAuth):** https://github.com/box/mcp-server-box-remote and https://developer.box.com/guides/box-mcp. It gives AI agents search and read access to Box content. The Box admin has to enable it. The older self-hosted community Python MCP server is listed as deprecated. The ERP can act as an MCP client for `erp_chat`, but this should come after the REST connector.
- **Rate limits and plans:** about 1,000 API requests per minute per user, and uploads limited to 240 per minute per user (https://developer.box.com/guides/api-calls/permissions-and-errors/rate-limits). Monthly API-call allowances depend on the plan (https://www.box.com/pricing). Sources disagree for the entry tier (25K vs 50K per month), so I could not verify the figure. Box itself is a paid SaaS for business use.

## Priority: 3/5 — useful where Box is the shared drawing channel; best built as the first provider of a generic cloud-drive layer rather than a one-off
