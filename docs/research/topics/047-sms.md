# 047. SMS notifications and two-way SMS (Twilio, Vonage, MessageBird, open-source gateways)

## What it does
Sends short text alerts from the ERP to phones (RFI answered, change order approved, inspection scheduled, safety incident, bid deadline) and accepts replies by SMS. Two-way SMS lets a site foreman or subcontractor who never opens the web app reply "YES" to confirm a delivery, "DONE 12" to close a punch item, or send a short field note that lands in the right project. Works on any phone, with no app install, and gets through where data coverage is poor.

## Already in the codebase (with file paths)
- **No SMS support.** A grep for `sms`, `twilio`, `vonage` and `messagebird` across `backend/app` finds nothing.
- `backend/app/modules/integrations/`: a connector pattern for Slack, Teams, Telegram, Discord and email (`slack.py`, `teams.py`, `telegram.py`, `discord.py`, `email_service.py`). `whatsapp.py` uses the Meta Cloud API with `httpx` and is marked "Coming Soon".
- `backend/app/modules/integrations/models.py`: `IntegrationConfig` (`oe_integrations_config`) stores per-user connector credentials in a JSON `config` column. `WebhookEndpoint` and `WebhookDelivery` handle outgoing webhooks.
- `backend/app/modules/notifications/events.py` and `service.py`: event-bus subscribers create in-app notifications (`notify_users`). This is the natural fan-out point for an SMS channel.
- There is no inbound webhook receiver for messaging, and no phone-number field or opt-in/opt-out store.

## Who it helps and how much
- **Field crews and subcontractors** who do not use the web UI. This is the main gain for small firms, where most of the workforce is on site.
- **Owner/estimator**: instant alerts for approvals and bid deadlines.
- **Value: Medium.** It helps, but Telegram, WhatsApp and email already cover office users. Two-way SMS is what sets it apart from those channels, but it adds compliance work (US A2P 10DLC registration, opt-out handling).

## Implementation effort
**Medium.** It touches `integrations` and `notifications`, plus a small migration.
1. Add `integrations/sms.py` with a provider interface `send_sms(to, body)` and `parse_inbound(request)`. Write the Twilio and Vonage adapters with raw `httpx`, as `whatsapp.py` already does, so no SDK dependency is needed. Optionally add an `apprise` backend for long-tail providers.
2. Add the `IntegrationConfig.integration_type = "sms"` config: provider, credentials, sender number.
3. Add an inbound route `POST /api/v1/integrations/sms/inbound/{provider}` that verifies the Twilio `X-Twilio-Signature` or the Vonage JWT. It maps the sender number to a user/contact, parses simple commands, and publishes an `sms.received` event. RFI, punchlist and fieldreports can subscribe to that event, so no module is coupled to SMS.
4. Store opt-in/opt-out (STOP/START) in a table, add a per-user phone number and quiet hours, and put all SMS templates through i18n.
5. Add validation rules: E.164 phone format, consent present before sending, and a 160-character/segment warning.
6. Follow AI-confirmed rules for inbound parsing: anything an LLM interprets from free text is a suggestion for review, never an automatic action.

## Building blocks
- **Twilio Programmable Messaging**: about $0.0083 per US segment plus carrier fees, and number rental. US 10DLC registration is mandatory. https://www.twilio.com/en-us/sms/pricing/us and https://www.twilio.com/docs/messaging/compliance/a2p-10dlc
- **Twilio MCP server** (`@twilio-alpha/mcp`, from Twilio Labs, alpha). It exposes Twilio APIs as MCP tools and could let `erp_chat`/AI agents send SMS. The repo shows both MIT and ISC license labels, so check its LICENSE file before relying on either. https://github.com/twilio-labs/mcp
- **Vonage Messages/SMS API**: around $0.007–0.008 per US outbound according to third-party comparisons, so check the official pricing page. Inbound webhooks are JWT-signed. https://developer.vonage.com/en/messages/code-snippets/inbound-message
- **Bird (formerly MessageBird)**: SMS availability and pricing on the current Bird site are unclear. One comparison says SMS is listed as "coming soon", and I could not confirm current pricing from Bird's own pages. Treat it as low priority. https://resources.rework.com/tools/messaging-sms/best-messagebird-alternatives
- **Apprise** (BSD-2-Clause, Python): one URL scheme covers about 40 SMS providers, including Twilio, Vonage, MessageBird, Plivo, Sinch and ClickSend. It is send-only, but good for a "bring any provider" option. https://github.com/caronc/apprise
- **SMS Gateway for Android** (Apache-2.0): turns an Android phone with a local SIM into a REST SMS gateway. It has a private-server mode and `sms:received` webhooks. This is the cheapest option for a very small firm, but it suits low volume only, and carrier terms may apply. https://github.com/capcom6/android-sms-gateway
- **textbee** (MIT): an Android-phone gateway with a REST API and webhooks. https://textbee.dev/docs
- No official Vonage or Bird MCP server was found and verified.

## Priority: 3/5 — useful for reaching field crews without app installs, but it overlaps the planned WhatsApp/Telegram channels and adds per-message costs and US/EU compliance work.
